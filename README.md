# go-gc-spike

Goの120秒タイマーによる強制GC(`forcegcperiod`)が、どのワークロードでどれだけ効くかを確かめるための検証プログラムです。
記事「「Pure Goで687万ops/sec」と「Goを捨ててRustへ」は矛盾するのか、GCのソースコードと再現実験で読み解く」の実験に使ったコードと、記事に載せた数値の元になった計測結果を置いています。

Go標準ライブラリだけで動き、外部の依存はありません。

## モード

プログラムは3つのモードを持ちます。

| モード | 再現するワークロード | 内容 |
|---|---|---|
| `kv` | VortexKV型のKVストア | 256シャード(パディング付き)の`map`に10万キーを置き、GET/SETを繰り返します。ソケットの代わりに事前に組み立てたRESPコマンド列を読み、パースと上書きをゼロアロケーションで行います |
| `spike` | 高アロケーション×大ヒープ | ポインタの多い500MBのライブヒープを保持しつつ、約1GB/sでアロケーションします |
| `force` | Discord型のキャッシュ | ポインタの多い600MBのライブヒープを保持し、アロケーションは約0.9MB/sだけにします。ヒープ成長によるGCが起きず、120秒タイマーだけがGCを起こす状態を作ります |

計測は、構築中のGCを除外するために`runtime.GC()`を1回呼んでから始めます。
その後は1秒ごとに`runtime.ReadMemStats`を呼び、`PauseNs`の環状バッファから新しく起きたGCのSTW時間を読み取ります。
GCの発火時刻は、この1秒の幅までしか特定できません。

## 実行方法

DockerでGo公式イメージ(`golang:1.27.3`)を使います。

```sh
./run.sh
```

`run.sh`は、ビルドしたあと次の5つの計測を順に実行し、結果を`results/`にJSONで書き出します。
全体で約8分かかります。

| 結果ファイル | モード | GOGC | 計測時間 | ワーカー数 |
|---|---|---|---|---|
| `kv10.json` | kv | 100 | 10秒 | 16 |
| `kv140.json` | kv | 100 | 140秒 | 16 |
| `spike15.json` | spike | 100 | 15秒 | 2 |
| `force_off.json` | force | off | 145秒 | 2 |
| `force_100.json` | force | 100 | 145秒 | 2 |

コンテナはCPU 2コア、メモリ4GBに制限しています(`--cpuset-cpus=0,1 --memory=4g`)。
spikeとforceの読み取りワーカーを2にしているのは、2コアに16本を載せるとプリエンプション待ちが遅延を支配するためです。

個別に動かす場合は、次のようにします。

```sh
go build -o gcbench .
GOGC=100 ./gcbench -mode force -d 145s -w 2
```

| フラグ | 既定値 | 意味 |
|---|---|---|
| `-mode` | `kv` | `kv`、`spike`、`force`のいずれか |
| `-d` | `10s` | 計測時間 |
| `-w` | `16` | 計測用ワーカー数 |

## 出力

標準出力に1行のJSONを書き出します。
主なフィールドは次のとおりです。

| フィールド | 意味 |
|---|---|
| `live_heap_mb` / `heap_objects` | 計測開始時点のライブヒープとオブジェクト数 |
| `num_gc` / `gc_at_sec` | 計測中のGC回数と、各GCを観測した秒 |
| `stw_total_us` / `stw_max_us` | STW時間の合計と最大(µs) |
| `alloc_mb_per_sec` / `bytes_per_op` | アロケーションレートと1操作あたりの確保量 |
| `ops_per_sec` | 1秒あたりの操作数 |
| `lat_max_us` / `lat_over_1ms` / `lat_over_1ms_pct` | 1操作の最大レイテンシと、1msを超えた件数・割合 |
| `samples` | 1秒ごとのGC回数とアロケーション量 |

## 同梱の計測結果

`results/`の結果は、次の環境で各モード1回ずつ計測したものです。
ばらつきは確認していません。

- Go 1.27.3(Docker公式イメージ`golang:1.27.3`)
- Linux arm64コンテナ(OrbStack、ホストはApple M2 Pro)
- `--cpuset-cpus=0,1 --memory=4g`

コンテナ上での計測なので、レイテンシの外れ値にはVMやスケジューラの影響が含まれます。
GCが1回も起きない`force_off`でも、1msを超える読み取りが82件出ています。
